# CONSTRAINTS — качественная планка KORGAN Legal AI

Контракт качества для ветки `claude/korgan-legal-document-quality-v1vgeo`.
Планку нельзя понижать молча: любое ослабление порога, пропуск теста, снятие
проверки — отдельное решение, которое обосновывается в теле PR.

---

## C1 · Юридическая достоверность (hard)

| # | Ограничение | Проверка |
|---|---|---|
| C1.1 | Точная ссылка на норму РК допускается в клиентском документе только если она прошла source-bound проверку (`adilet.zan.kz` / `zan.gov.kz`) или найдена в датированном корпусе | `citation_audit.audit_citations` |
| C1.2 | Неподтверждённая ссылка выпускается только с явным маркером и статусом `NEEDS_VERIFICATION`, тихий выпуск запрещён | `document_release.review_lines` |
| C1.3 | Пересказ нормы сверяется с её собственным текстом; расширение узкого условия блокирует | `provision_check.paraphrase_defects` |
| C1.4 | Неофициальный сайт может использоваться для поиска, но не как финальное доказательство нормы | `legal/official_sources.official_source_kind` |
| C1.5 | Для verified law хранятся: `act_title`, `article`, `paragraph`, `official_url`, `checked_at`, `effective_at_relevant_date`, `verification_status` | `provision_corpus.ProvisionRecord` |

## C2 · Zero invention (hard)

| # | Ограничение |
|---|---|
| C2.1 | Никогда не изобретаются: ФИО, БИН/ИИН, адрес, номер договора, дата, сумма, доказательство, факт оплаты, факт направления претензии |
| C2.2 | `MISSING_FACT` не превращается в правдоподобное предположение — только пробел или пометка |
| C2.3 | Известный из материалов ИИН/БИН не теряется при сборке документа |
| C2.4 | Иск истца не содержит прогнозируемых возражений ответчика («ответчик может утверждать/возражать», «Возражения ответчика», «Позиция ответчика») |

## C3 · Воспроизводимость расчётов (hard)

| # | Ограничение |
|---|---|
| C3.1 | Каждое денежное требование раскрывается как: основание · база · ставка · период · дни · формула · итог |
| C3.2 | Все денежные вычисления — `Decimal`, `ROUND_HALF_UP`, никогда `float` |
| C3.3 | Договорная неустойка не подменяется расчётом по ст. 353 ГК РК |
| C3.4 | Ставки и потолки госпошлины читаются только из `korgan/data/rates.json` |
| C3.5 | При нехватке данных расчёт не выполняется; результат не выдумывается |
| C3.6 | Юридические услуги и судебные расходы — отдельные позиции |
| C3.7 | Одинаковый вход даёт побайтово одинаковый расчёт |

## C4 · Профессиональный стиль (hard)

Во внешнем тексте документа запрещены:
`AI считает` · `возможно, суд` · `скорее всего` · `рекомендуется проверить` ·
`NEEDS_VERIFICATION` · `reasoning` · `internal notes` · системная терминология ·
`KORGAN pipeline` · `SENIOR_PREFLIGHT_SCORE` · `KORGAN QUALITY` ·
`FILING_ACTION`.

Документ не раздувается искусственно, но сложный иск не сводится к одной
странице.

## C5 · Quality gates (hard)

| # | Ограничение |
|---|---|
| C5.1 | Ответ модели не является готовым документом; до DOCX выполняются все 14 аудитов из SPEC §M6 |
| C5.2 | Существенная ошибка блокирует релиз либо переводит документ в `preliminary` |
| C5.3 | Все четыре типа документа имеют численный quality gate с одинаковым порогом |
| C5.4 | Порог `filing_ready` — 10.0/10 при отсутствии hard blockers (текущее production-поведение, не понижается) |

## C6 · Тестирование (hard)

| # | Ограничение |
|---|---|
| C6.1 | Полный `pytest` из корня зелёный. Прогон только по отдельным файлам не считается зелёным |
| C6.2 | Каждый исправленный production-баг имеет регрессионный тест, который падал до фикса |
| C6.3 | Тесты денежных вычислений выполняются в двух режимах: без production-патчей и после `import korgan.strict_bot` |
| C6.4 | Тест не отключается, не пропускается и не удаляется ради зелёного статуса |
| C6.5 | Тесты не ходят в сеть и не вызывают OpenAI |

## C7 · Сохранность существующего MiniApp (hard)

Не нарушаются: оплата Kaspi/OFD · идемпотентность · сохранение документов ·
«Мои дела» · аутентификация · PostgreSQL · контракты MiniApp API ·
загрузка PDF/DOCX/JPG/PNG · существующие гарантии безопасности и приватности.

**C7.1** Ошибка генерации после подтверждённой оплаты никогда не требует
повторной оплаты: ордер остаётся `approved`, пользователь получает повтор.

## C8 · Технический долг (soft, но с процедурой)

Giant rewrite запрещён. Если несколько патчей делают одно и то же:

1. доказать дублирование тестами;
2. определить каноническую реализацию;
3. аккуратно мигрировать;
4. удалить zombie-код только после regression coverage.

**C8.1** Новые монки-патчи не добавляются. Существующий патч либо делегирует
канонической реализации, либо удаляется.

**C8.2** Новый модуль создаётся только после доказательства, что существующий
исправить нельзя.

## C9 · Git (hard)

- База и цель PR — `recovery/miniapp-api-1600-sg`.
- `main` не используется. Force-push запрещён. Прямые коммиты в production base
  запрещены.
- Маленькие логические коммиты.

- [ ] production branch определена правильно
- [ ] реальный document pipeline изучен
- [ ] существующие дубли/hotfixes проанализированы
- [ ] иски профессионального качества
- [ ] досудебные претензии профессионального качества
- [ ] ответы на претензии профессионального качества
- [ ] отзывы на иски профессионального качества
- [ ] нет выдуманных фактов
- [ ] нет выдуманных статей
- [ ] проверяется актуальность законодательства
- [ ] проверяется применимость нормы
- [ ] расчёты воспроизводимы
- [ ] внутренний reasoning не попадает в документы

- [ ] полный существующий test suite зелёный
- [ ] code review пройден
- [ ] security audit пройден
- [ ] test-engineer review пройден
- [ ] PR смержен именно в `recovery/miniapp-api-1600-sg`
