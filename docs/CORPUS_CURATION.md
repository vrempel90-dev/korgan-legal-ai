# Наполнение корпуса норм — инструкция для юриста

Этот документ описывает, как добавлять и обновлять нормы права без обращения к разработчику.
Содержание норм — ваша работа; система отвечает за то, чтобы запись была полной, отслеживаемой
и реально использовалась при подготовке документов.

## Что нужно для одной записи

| Поле | Обязательно | Что это |
|---|---|---|
| `--code-id` | да | Код источника: `GK_RK_GENERAL`, `GPK_RK`, `TAX_RK_2025`, `LABOR_RK` и т.п. |
| `--article` | да | Номер статьи |
| `--part` / `--point` | если есть | Часть и пункт |
| `--text` / `--text-file` | да | **Дословный** текст нормы — он попадает в цитату документа |
| `--effective-from` | да | Дата вступления редакции в силу |
| `--effective-to` | нет | Дата окончания, если редакция уже закрыта |
| `--source-url` | да | Ссылка на официальный источник (adilet.zan.kz, zan.gov.kz, gov.kz) |
| `--reviewed-by` | да | Кто сверил текст с источником |
| `--law-name`, `--title` | желательно | Полное название кодекса и заголовок статьи |
| `--document-types` | желательно | К каким типам дел норма применима |
| `--next-review` / `--review-months` | нет | Когда перепроверить; по умолчанию +6 месяцев |

Кто и когда подтвердил норму, хранится в тех же полях, что и раньше (`reviewed_by` / `reviewed_at`),
отдельной пары `verified_by`/`verified_at` нет специально: один механизм подтверждения, чтобы запись
не могла оказаться подтверждённой в одном поле и неподтверждённой в другом.

## Перед началом

```bash
export DATABASE_URL=postgresql+psycopg://...
```

## Добавить норму

Длинный текст удобнее передавать файлом — так его не портит оболочка:

```bash
korgan-legal add-norm \
  --code-id GK_RK_GENERAL --article 272 \
  --law-name "Гражданский кодекс Республики Казахстан (Общая часть)" \
  --title "Исполнение обязательства надлежащим образом" \
  --text-file ./gk-272.txt \
  --effective-from 2026-01-01 \
  --source-url "https://adilet.zan.kz/rus/docs/K940001000_" \
  --reviewed-by "Иванова А.К." \
  --document-types "claim,pretrial_demand"
```

Команда откажет, если данных не хватает, и перечислит **все** проблемы сразу, а не по одной.

## Проверить источник

```bash
korgan-legal verify-source "https://adilet.zan.kz/rus/docs/K940001000_"
```

Ссылка не на официальный источник не блокируется жёстко, но сохранить такую норму можно только
с флагом `--allow-unofficial-source`. Учтите: Citation Gateway не пометит ссылку на неё как
проверенную, поэтому **в документах она не появится**.

## Обновить норму (новая редакция закона)

```bash
korgan-legal update-norm \
  --code-id GK_RK_GENERAL --article 272 \
  --text-file ./gk-272-new.txt \
  --effective-from 2026-07-01 \
  --source-url "https://adilet.zan.kz/rus/docs/K940001000_" \
  --reviewed-by "Иванова А.К."
```

Предыдущая редакция **не перезаписывается**: она закрывается днём раньше новой и остаётся в
корпусе. Документ, подготовленный в мае, по-прежнему воспроизводится против той редакции, которая
действовала в мае.

Опечатку в редакции, которая не менялась, исправляют отдельно и явно:

```bash
korgan-legal update-norm ... --effective-from 2026-01-01 --correct-in-place
```

## Что пора перепроверить

```bash
korgan-legal list-pending
korgan-legal list-pending --as-of 2027-03-01
```

Просроченная норма продолжает работать — истёкший срок проверки не делает текст неверным, — но
в документе рядом с ней появляется пометка «требует переверификации», чтобы её не приняли за
свежесверенную.

## Сколько это дало

```bash
korgan-legal coverage-report
korgan-legal coverage-report --include-acceptance
```

Отчёт сравнивает текущее состояние с базовой линией (пустой корпус) и показывает:

- сколько блокеров NEEDS_VERIFICATION по нормам было и сколько осталось;
- какая доля снята;
- сколько из оставшихся ждут именно нормы, а сколько — фактов по делу (последние наполнением
  корпуса не закрываются);
- вклад каждой нормы: сколько пунктов в каких кейсах она перевела в подтверждённые.

Мера успеха — снятые блокеры, а не число внесённых статей: норма, которая никому не нужна, ничего
не двигает.

## Спорные вопросы толкования

Иногда закон или договор допускают несколько прочтений, и системе нужно выбрать одно. Такие решения
хранятся отдельно от норм — это не текст закона, а позиция фирмы:

```bash
korgan-legal position-list
korgan-legal position-set \
  --key penalty_cap_base \
  --decision defaulted_debt \
  --rationale "Потолок считается от долга на дату просрочки; иначе полностью погашенный долг получил бы потолок 0." \
  --decided-by "Юридический отдел" \
  --practice "СМЭС г. Алматы, дело № 2-1234/2025" \
  --confirmed
```

Изменение позиции меняет расчёт **без изменения кода**. Если решение не зафиксировано,
`position-list` покажет вопрос как открытый и укажет, какое значение применяется по умолчанию.

## Чего инструмент не делает

Он не проверяет, что вы внесли верный текст, что норма действует и что она применима к делу.
Он гарантирует только полноту записи, сохранность прежних редакций и то, что непроверенное
не попадёт в документ молча.
